# Studio unification

How core's `Studio\Studio` was unified from the three addons' `Studio` classes, as of Statamic `7f16bf0`, Filament `9f0c565` and Craft `f15d1d2`. Code style, comments and CMS names in docblocks were ignored when comparing.

"Default" means `new StudioOptions()`. `StudioOptions::statamic()`, `::craft()` and `::filament()` give each addon's behaviour where it is kept as an option.

## Options

| Option | Default | Statamic | Craft | Filament | What it changes |
|---|---|---|---|---|---|
| `logReplies` | `false` | `false` | `false` | `false` | Puts the whole model reply in the log context (`reply`) when it can't be read. See F8 below. |
| `exampleDepth` | `100` | `100` (its `YAML::dump`) | `12` | `20` | How deep example entries are written out as YAML before nesting goes inline. |
| `unpublishedLabel` | `draft` | `draft` | `draft` | `not published` | The planner's marker for an entry that isn't live: `- Title (draft)`. |
| `variantLabel` | `blueprint` | `blueprint` | `entry type` | (unused) | The kind finder's word for a blueprint or entry type: `· entry type: News`. |
| `missingKindsIsEmpty` | `false` | `true` | `false` | `false` | A kind finder reply with no `<kinds>` block is "nothing to add" rather than unreadable. Statamic's prompt invites it (`[[kinds_when_none]]`). |
| `cutOffMessages` | core's four | its own for `voice-analyst` | one message for all four | its own for `type-analyst`, `voice-editor` | What a person is told when a draft or guide is still cut off after the retry. |

## Calls (`ask`)

| What differed | What core does |
|---|---|
| Statamic and Filament left `maxTokens` and `effort` to `Agents`; Craft set them on the request from `Agents`. | Left to `Agents` (`null` on the request). The values sent are the same: `RequestLog` records the resolved values, so a parity check sees no difference. |
| Craft threw `Truncated` for **every** agent still cut off after the retry, with one message. Statamic and Filament followed §6.6. | §6.6 for all: `writer`, `type-analyst`, `voice-analyst` and `voice-editor` throw `Truncated` (message from `cutOffMessages`); every other agent keeps what came back, with a warning. **For Craft, a cut-off plan, kind list, brief or imagery guide is now kept rather than failing.** |
| Statamic and Filament logged the retry and the "keeping it" at warning; Craft logged neither. | Both are logged at warning, with agent, provider and model. |
| Each kept the usage of the last call only. | `usage` counts every call a job made: the retry with more room, and the type analyst's re-ask. Counts can be a little higher than before in those cases. |
| The logger: Laravel's `Log` (Statamic), `Log::channel(config('ghostwriter.log_channel'))` (Filament), `Craft::warning(..., 'ghostwriter')` (Craft). | One optional PSR-3 logger, passed to the constructor. |

## F8: unreadable replies in the log

All three logged the model's whole reply when it couldn't be read (Filament `Studio.php:156`, Statamic `:142,153,219` and its `report()` calls, Craft `:115,125,190`).

Core logs only what was wrong: "the type analysis for articles could not be read (there was no `<type>` block); asking again". A YAML failure is logged as "the YAML did not parse at line 3", without the parser's message, which quotes the text near the fault. The model still gets the parser's whole message in the re-ask, as before.

With `logReplies` on, the whole reply is added to the log context under `reply`. It is never put in the message. Prompts, instructions and keys are never logged in either mode. An addon should turn it on only from a debug setting.

## Left in the addons

- Reading the CMS: schemas, patterns, entries, prose, parents, blueprints and entry types, and choosing which entries to show.
- Building and saving their own types and ideas from core's results (handles, `TypeRepository::handleFor()`, `Kinds`, the plan's state).
- `provider()` and `configured()` as their settings see them (Filament's `Keys::canWrite()`). Core's `configured()` asks the registry.
